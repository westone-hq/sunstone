# 기능 구현 시작 안내

`routines/`(① 기능 구현)을 맡는 박희정을 위한 문서다. 승인과 최종 결정은 대표 박건준이 한다. 구조는 `docs/STRUCTURE.md`, 규칙은
`docs/COMMENT_RULES.md`를 먼저 읽는다.

---

## 1. 맡는 일

| 할 일 | 위치 | 끝났다고 보는 기준 |
|---|---|---|
| 루틴 (1차 3개, 2차 2~4개) | `routines/library/` | 대표가 단계·문장·숫자를 승인했고 테스트가 있다 |
| 실행 엔진 | `routines/engine/` | 저장→실행→확인→안내 대체→되돌리기가 모든 루틴에서 같다 |
| 말 알아듣기 | `routines/understand/` | 대사집의 모든 사용자 대사와 변형이 맞게 풀린다 |
| 대화 흐름 | (예정) `routines/dialog/` | 길안내→주유 제안→세차 추천→도착 시 권하기가 끊기지 않는다 |
| 문장 틀 | (예정) | 같은 상황에 같은 문장. 숫자·이름만 끼운다 |
| AI 참고 문서 | (예정) `app/src/main/assets/` 데이터 + `routines/knowledge/` 읽기 | 기능 카드가 대표 승인을 받았다 |
| 대사집 + 자동 테스트 | (예정) `routines/script/` + 테스트 | S0~ 전 장면이 JVM 테스트로 통과한다 |

필요하면 넘겨받을 수 있는 일: 바깥 API 5종 연결, 음성 녹음본. 넘길 때는 대표가 정한다.

맡지 않는 일: Pleos SDK 호출, 내비 SDK, 화면, 마이크·TTS, 시연 빌드, 시연 영상.

## 2. 진행 방식 (승인 먼저)

지금 코드에 있는 루틴·문장·숫자는 **초안**이다. 기능은 하나씩 이 순서로 다시 만든다.

1. **설명**: 만들 기능을 짧게 적는다(언제 켜지나, 단계, 하는 말, 판단 숫자, 안 되는 경우).
2. **승인**: 대표가 고치거나 승인한다. 승인 전에는 코드를 쓰지 않는다.
3. **테스트 먼저**: 승인된 설명을 테스트로 옮긴다(가짜 차, 가짜 창구).
4. **구현**: 테스트를 통과시킨다.
5. **기록**: 무엇을 만들었고 무엇이 미구현인지 relay에 남긴다.

설명 양식:
```
기능: 세차 모드
켜지는 때: "세차할게" / 세차장 도착 + 정차
단계: 창문 닫기(제어) → 선루프 닫기(제어) → 와이퍼 끔(제어) → 미러 접기(안내) ...
하는 말: 시작 / 단계 실패 시 / 끝날 때
판단 숫자: 떠났다고 보는 속도 10km/h (근거: 미정)
되돌리기: 와이퍼·내기순환 원래대로. 창문은 다시 열지 않음
안 되는 경우: 주행 중이면 시작하지 않고 "정차 후에 할게요"
```

## 3. 권장 방식

- **대사집부터.** 시연 대사가 곧 테스트다. 장면 하나를 승인받으면 그 장면 테스트부터 쓰고 코드를
  맞춘다. 완성 기준이 "시연대로 끝까지 도는가"라서 이 순서가 가장 빠르다.
- **1차 루틴 3개를 먼저 끝까지.** 대화 흐름은 세차 루틴이 다 된 뒤에 붙인다. 흐름의 마지막이 세차
  모드 권하기라서.
- **판단은 규칙으로.** 실행할지 말지는 상태 조건(정차, 기어 P, 뒷좌석 탑승 등)으로만 정한다. LLM을
  붙여도 말 풀이와 문장 다듬기만 맡긴다. 시연 중 판단이 흔들리면 안 된다.
- **안 되는 건 말로.** 앱이 못 하는 단계(미러 접기, 차일드락 스위치 등)는 지우지 말고 안내 단계로
  둔다. "앱이 할 수 있는 건 하고, 못 하는 건 정확히 알려 준다"가 이 앱의 핵심이다.
- **창구는 작게.** 기능 쪽에서 필요한 값만 창구에 넣는다. 내비 창구에 SDK 객체를 그대로 넘기지
  않는다. 테스트가 쉬워지고 앱 쪽 교체도 쉽다.
- **문장은 한곳에.** 루틴 안에 문장을 흩어 쓰지 말고 문장 틀 한곳에 모은다. 대표가 문장만 고칠 수
  있게.
- **참고 문서 카드는 짧게.** 기능 하나 = 카드 하나 = 200~400토큰. 별칭으로 찾고 상위 3개만 쓴다.
  사용자 기억(방문 기록, 마지막 세차일)은 검색하지 않고 바로 꺼낸다.

## 5. 차 쪽에서 확인된 것 / 안 된 것

`docs/api-spike.md`가 최신이다. 시작 시점 기준:

| 항목 | 상태 |
|---|---|
| 차 값 읽기(기어·문·좌석·벨트·창문) | Playground 콘솔 "사용 가능" |
| 차 제어(창문·와이퍼·공조·문 잠금·시트) | 콘솔 "준비 중". 다른 팀은 권한 선언만으로 에뮬레이터에서 됨. 실측 필요 |
| 미러 접기, 기어/주차 브레이크, 차일드락 스위치 | API 없음 → 안내 단계 |
| `selectSeatMemory` | 성공 콜백 없음 → 다시 읽어 확인 |
| 내비(경로·경유지 최대 2·남은 거리·도착) | NaviHelper 3.0.5 사용 가능. 장소 분류 검색은 없음 → 카카오 |
| TTS·STT | 콘솔 "준비 중" → 안드로이드 기본 TTS·음성 인식 사용 |

---

## 6. 시작 순서

1. `.\gradlew :routines:test` 가 통과하는지 본다.
2. `docs/STRUCTURE.md` 3장 창구 표를 보고, 대화 흐름에 필요한 창구 초안을 relay로 제안한다.
3. 세차 모드 설명(2장 양식)을 써서 대표 승인을 받는다.
4. 승인되면 테스트 → 구현. 이어서 차일드락, 시트 메모리.
