# 날씨 조회 실패 진단 및 수정

2026-11-14, Pleos 에뮬레이터 `Sunstone_Pleos` 실제 검증.

## 확인된 원인

예전 앱 로그에는 `Read timed out`, 재현 중에는 `Connection reset`이 나타났다.
예보 JSON을 해석하기 전에 HTTPS 통신이 실패했다. 기존 클라이언트는 한 번 실패하면
즉시 확인 불가를 반환했으므로 일시적인 연결 장애를 회복하지 못했다.

PC에서도 처음에는 연결 시간 초과가 있었으나 이후 동일한 HTTPS 요청이 HTTP 200으로
정상 응답했다. 시스템 DNS와 공개 DNS를 비교하고 각 DNS 주소에 원래 호스트명으로 TLS 검증을
유지해 접속했을 때도 성공했다. DNS 오설정이나 인증서 오류라고 확정할 근거는 없다.
연결을 끊은 네트워크 장비·서버의 내부 원인까지는 확인되지 않았다.

## 수정 파일

- `app/src/main/java/com/westone/sunstone/info/WeatherRequests.kt`: 통신 IOException에만
  400ms 후 한 번 재시도. 두 번째 실패는 그대로 전달한다. 인증서 검증·호스트명 오류,
  취소, HTTP 오류, JSON 오류는 재시도하지 않는다. HTTP 429 제한도 우회하지 않는다.
- `info/OpenMeteo.kt`: 각 시도마다 HTTPS 연결을 새로 열고 종료한다. 응답 호스트와 소요 시간 기록.
- `info/LiveInfo.kt`: 두 번의 연결·읽기 시도를 허용하도록 세차 조회 코루틴 제한을 8초에서 16초로 조정.
- `info/WeatherConversation.kt`: 지역 검색과 예보가 각각 재시도할 수 있도록 전체 제한 35초 적용.
  강수 판정 결과와 보류 사유를 로그에 기록한다.
- `app/src/test/java/com/westone/sunstone/info/OpenMeteoTest.kt`: 연결 끊김 후 성공,
  연속 시간 초과 후 확인 불가, 인증서·취소·응답 오류 재시도 금지 검증 추가.
- 관련 문서 `WEATHER.md`, `SCENARIO_ONE.md` 갱신.

연결 제한 3초, 읽기 제한 4초는 각 시도에 적용된다. 코루틴 취소는 유지하며,
플랫폼의 블로킹 네트워크 작업은 연결·읽기 제한 시점에 종료될 수 있다.
재시도에 실패하면 계속 확인 불가로 처리하며 가짜 예보나 임의 좌표를 사용하지 않는다.

## 실제 검증 결과

- 전체 테스트 118개 통과, 실패·건너뜀 0. 실제 카카오와 Open-Meteo 테스트 포함.
- `assembleDebug` 성공, 수정 APK 에뮬레이터 재설치 성공.
- 출장 시나리오 버튼 → 사용자 서울역 입력 → 카카오 후보 선택 → 기존 Pleos 길안내 성공.
- 카카오에서 선택한 말죽거리주유소 좌표 `37.485179330454, 127.040663514941`로 예보 조회.
- 13:32:42 첫 시도 SocketException → 13:32:43 두 번째 시도 HTTP 성공(866ms).
- 13:32:44 `RAIN_EXPECTED` 판정. 실제 TTS에서 “일주일간 비 예보가 있어서 세차는
  추천드리지 않아요” 안내. 카드에 “7일 내 비 예보 있음”, 버튼에 “주유소 경유 / 경유 안 함” 표시.
- 13:33:28 서울 내일 예보 조회 성공. `NO_RAIN_EXPECTED`, 최대 강수확률 18%,
  최대 비의 양 0.0mm/h 음성 안내. 이는 검증 당시 실제 응답이며 고정한 값이 아니다.
- 실패·비 없음·비 있음 분기는 자동 테스트에서도 검증한다. 실제 비 없음 주유소의
  전체 세차 동작은 이번 진단에서 다시 실행하지 않았다. 기존 차량 제어 코드는 수정하지 않았다.

요청 실패와 별개로 강수확률이 높지만 비·눈 형태를 확인할 수 없는 자료는 기존 보수적인
판정 정책에 따라 여전히 확인 불가가 될 수 있다. 이를 비 없음으로 바꾸지 않았다.
